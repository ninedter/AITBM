PUBLIC-EVIDENCE AI SECURITY CASE STUDY

Miasma Targets Repository-Local Trust in Claude Code, Gemini CLI, Cursor, and VS Code

On 2026-06-05 a previously compromised contributor account pushed commit 5f456b8 to Azure/durabletask. The commit was backdated, carried [skip ci], added five files, and changed no application source. Four of the files were repository-local trigger configurations; the fifth was a 4.6 MB obfuscated .github/setup.js credential harvester. Opening the project could launch that payload through Claude Code or Gemini CLI SessionStart hooks or a Cursor always-applied rule — and, on a separate non-AI path outside this assessment, a VS Code folder-open task. Once launched the harvester ran with the developer process's local access. GitHub later disabled 73 repositories across four Microsoft organisations in two automated waves; StepSecurity confirms the malicious commit in Azure/durabletask but does not establish that the payload propagated into every disabled repository.

On 2026-06-05 a previously compromised contributor account pushed commit 5f456b8 to Azure/durabletask. The commit was backdated, carried [skip ci], added five files, and changed no application source. GitHub later disabled 73 repositories across four Microsoft organisations in two automated waves; StepSecurity confirms the malicious commit in Azure/durabletask but does not establish that the payload propagated into every disabled repository.

ASSESSED SYSTEM

An AI coding agent — Claude Code, Gemini CLI, or Cursor — in its default repository-local trust configuration, opening a checked-out repository inside a developer session that carries cloud, Git, package-registry, and Kubernetes credentials. In that configuration the agent reads repository-local configuration (.claude/settings.json, .gemini/settings.json, .cursor/rules/setup.mdc) and acts on it without a signature check or an attributable activation decision, so a SessionStart hook or an always-applied rule can launch a repository-supplied executable on project open. Representative configuration: any AI coding agent that treats repository-local configuration as trusted directive material at session start.

OUT OF SCOPE

The .vscode/tasks.json folder-open route is explicitly excluded from the assessed system: the brief states it involves no AI participation, and both the AID-H-021.001 and AID-H-021.002 defence descriptions disclaim coverage of that non-AI IDE trust path. Scoring it would mix a conventional IDE trust boundary into an AI-agent assessment. The compromised contributor account, the Azure/durabletask repository, and the .github/setup.js payload are the attack, not the assessed system. GitHub's platform response — 73 repositories disabled across four Microsoft organisations in a 105-second automated sweep — is a platform containment action outside the assessed boundary, and the brief states that the count describes containment scope, not a verified infection count.

Architecture: Agentic / MCP System (decision tree Q2) — Q1 = NO: one agent per session; no peer-agent coordination is described. Q2 = YES: the agent starts a session, reads repository-local configuration, and executes a configured command with the developer session's tool and credential authority, with no approval for that individual action. Evidence in the brief: the SessionStart hooks in .claude/settings.json and .gemini/settings.json, and the Cursor always-applied rule in .cursor/rules/setup.mdc that instructs the agent to run the script. This is an unattended, state-holding, tool-invoking workflow. Tier 3: Tier 3 (Internal): the assessed system is developer tooling operating inside the organisational boundary, which is the treatment already applied to the comparable AI-coding-agent configuration-poisoning and dependency cases. The credential blast radius — cloud, Git, package-registry, and Kubernetes secrets in the developer session — is carried by Cascade Potential (Cp = 1.00), not by raising the tier.

Documented attack or failure path

  1. A previously compromised contributor account pushes commit 5f456b8, backdated and carrying [skip ci], adding five files and changing no application source — a shape that repository admission ignoring editor and agent configuration leaves unreviewed.
  2. A developer clones or opens the repository in an AI coding agent session that holds cloud, Git, package-registry, and Kubernetes credentials.
  3. The agent reads repository-local configuration and acts on it: .claude/settings.json and .gemini/settings.json register SessionStart hooks, and .cursor/rules/setup.mdc supplies an always-applied instruction telling Cursor to run the script. No signature check and no attributable activation decision intervenes.
  4. Every trigger points at the obfuscated 4.6 MB .github/setup.js. It executes with the developer process's local access and harvests credentials.

Observed controls and bounded outcomes

Positive credit is given only where the record directly demonstrates a control operating. Recommended or merely presumed controls receive no positive scoring credit.

  • No control inside the assessed boundary is evidenced as having interrupted the disclosed path. The brief records containment only after execution was possible, and outside the assessed system: GitHub disabled 73 repositories in two automated waves.
  • The brief is explicit that the 73-repository figure describes containment scope rather than a verified infection count, so no downstream propagation is scored as either a failure or a control success.
  • StepSecurity confirms the malicious commit in Azure/durabletask only; no claim about other repositories' contents is scored in either direction.

WHAT THIS CASE TEACHES

Miasma moves supply-chain execution from package installation to project open, and AITBM records that as an identity failure as much as a containment one: Cn-5 scores 0.00 because nothing bound the agent's operating directive to a verified source, so a repository rather than the operator defined what the agent would do at startup. The non-AI VS Code route is deliberately excluded from the assessed system — the brief's own defence descriptions disclaim coverage of it, and folding it in would have mixed a conventional IDE trust boundary into an AI-agent score.
