Prompt-to-Shell: Dual RCE Paths in Microsoft Semantic Kernel

Microsoft documented two distinct Semantic Kernel prompt-to-host-RCE paths: a Python Search Plugin filter evaluated with eval(), and a .NET SessionsPythonPlugin file-transfer function exposed to model tool calling that could write a payload into the host Startup folder.

Why this record has no ERS

This AIDEFEND SecureFlow record is a curated attack flow built from public research reporting. It documents the demonstrated attack path and the applicable AIDEFEND controls, but it does not establish one bounded assessed deployment with a configuration, a complete evidence set, and measured control performance. Assigning IVP, ORP, ACI, or ERS values would invent system-specific evidence. The attack steps, ATLAS technique references, and the exact upstream defense set are retained as candidate evidence routes only.

Attack steps

#StepATLAS tactic / technique
1Obtain Prompt-Injection Vector into a Semantic Kernel AgentThe attacker supplies a crafted prompt to a Semantic Kernel agent that can invoke framework tools. Microsoft's demonstrations use prompt-controlled input to reach two different vulnerable tool paths; the branches below are separate vulnerabilities, not one chained exploit.AML.TA0005
AML.T0051.000
2Inject Python into the Vector-Store eval() FilterIn the Python branch, the default In-Memory Vector Store filter interpolates an AI-controlled Search Plugin argument into a lambda string and evaluates it with eval(). A quote-breaking value turns the intended city comparison into attacker-controlled Python syntax.AML.TA0005
AML.T0050
3Bypass the Blocklist via Class-Hierarchy TraversalThe payload remains a syntactically valid lambda while traversing Python's class hierarchy to find BuiltinImporter. It avoids blocked names and restores dangerous capability despite the empty __builtins__ environment.AML.TA0007
AML.T0107
4Import os and Run a Shell CommandThe payload loads os and invokes system() with attacker-controlled command text. Microsoft's proof of concept launched calc.exe from the agent process.AML.TA0005
AML.T0050
5Invoke [KernelFunction] DownloadFileAsync with an Attacker PathIn the separate .NET branch, SessionsPythonPlugin.DownloadFileAsync was marked [KernelFunction], exposing it to model tool calling. The AI-controlled localFilePath selected an arbitrary host destination for bytes fetched from the sandbox.AML.TA0005
AML.T0053
6Write Payload to the Host Startup FolderWithout path validation or a safe-directory restriction, the host-side transfer wrote the sandbox-created script into Windows\Start Menu\Programs\Startup, crossing the isolated dynamic-session boundary.AML.TA0005
AML.T0053
7Payload Executes on Next LoginAt the next user sign-in, Windows executes the script from the Startup folder, turning the arbitrary host file write into code execution.AML.TA0005
AML.T0050
8Remote Code Execution on the Agent HostEither branch can end in code execution with the privileges and reach of the Semantic Kernel agent host. The two branches converge on the same host-compromise outcome but do not depend on each other.AML.TA0011
AML.T0112.000
