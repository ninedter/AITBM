PUBLIC-EVIDENCE AI SECURITY CASE STUDY

Ray DNS Rebinding: A Malicious Page Reaches the Local Jobs API

CVE-2025-62593 affects Ray before 2.52.0. A developer running the Ray Dashboard on its default port can be compromised after visiting a malicious page or advertisement in Firefox or Safari. Ray blocked POST and PUT only when the User-Agent header began with 'Mozilla'; both browsers allow JavaScript to set another value, so the request no longer looked like browser traffic to the middleware. DNS rebinding then repointed the attacker's origin at port 8265 on localhost or a private Ray host, and page JavaScript submitted an unauthenticated job containing attacker-selected commands, which Ray executed. The advisory's proof of concept opens Calculator; broader payloads are possible but are not evidence of a specific observed campaign. CISA added the CVE to the Known Exploited Vulnerabilities catalog on 2026-08-17 without attributing the exploitation.

ASSESSED SYSTEM

A Ray installation before 2.52.0 running its Dashboard on the default port 8265 on a developer workstation or private host, in its pre-fix state: the Jobs API is unauthenticated, and the only barrier to browser-originated writes is middleware that blocks POST and PUT when the User-Agent header begins with 'Mozilla'. Representative configuration: any Ray deployment below 2.52.0 whose dashboard port is reachable from a browser process on the same host or private network.

OUT OF SCOPE

The attacker's page, advertisement, and DNS infrastructure are not the assessed system. Firefox and Safari are not assessed; the advisory states Chrome was not vulnerable through this header-setting path at disclosure time, and browser behaviour is context for reachability rather than a scored control. Ray 2.52.0 and later is out of scope. The KEV listing establishes exploitation without attribution or detail, so no victim, campaign, or payload outcome is scored.

Architecture: Traditional ML / Classifier (decision tree Q6) — The decision tree resolves at Q6 by elimination. Q1 = NO (no coordinating agents). Q2 = NO (the Jobs API executes submitted work; it holds no goal, plan, or task state of its own). Q3 = NO (no model invokes a function on this path; the dashboard middleware and job submission API are ordinary service endpoints). Q4 = NO (no retrieval layer). Q5 = NO (no generative interface participates in the disclosed path). What remains is distributed AI/ML compute infrastructure and its management API, which the classifier weight class represents. Tier 3: Tier 3 (Internal): the assessed surface is a development and internal-cluster management dashboard, and the advisory's own framing is a developer running the Ray Dashboard on its default port. Its remediation guidance — bind dashboards to a controlled interface, apply host firewall and network policy including on developer laptops and shared workstations — is internal-service guidance. The severity of arbitrary command execution is carried by Cascade Potential and the Containment scores, not by raising the tier.

Documented attack or failure path

  1. The victim loads content from the attacker's domain in Firefox or Safari.
  2. Subsequent DNS answers point that same origin at port 8265 on localhost or a private Ray host, so page JavaScript can address the dashboard from within the attacker's origin.
  3. Page JavaScript sets a non-Mozilla User-Agent value, defeating Ray's browser heuristic, so the middleware no longer treats the request as browser traffic and permits POST.
  4. The page submits an unauthenticated job to the Jobs API containing attacker-selected commands; Ray executes the supplied command on the host.

Observed controls and bounded outcomes

Positive credit is given only where the record directly demonstrates a control operating. Recommended or merely presumed controls receive no positive scoring credit.

  • A write-blocking control existed on the dashboard middleware and did stop ordinary browser POST and PUT traffic: the advisory's chain required an explicit header-setting step to defeat it, and it holds against browsers that do not permit that step. The advisory verifies Firefox and Safari and states that Chrome was not vulnerable through this header-setting path at disclosure time.
  • The advisory scopes the disclosed defect to the browser-origin heuristic and the unauthenticated Jobs API; the job execution engine itself is not characterised as defective.

WHAT THIS CASE TEACHES

Three boundaries each failed independently — an origin heuristic mistaken for identity, network reachability from a browser process to a management port, and an unauthenticated execution API — and the case scores 0.00 on all three Containment sub-metrics because a spoofable self-asserted header is not a control at any anchor. Ray 2.52.0 closes the disclosed path, but Cn-5 stays at 0.00 for any deployment that still authorises job submission by inspecting what the caller claims to be.
