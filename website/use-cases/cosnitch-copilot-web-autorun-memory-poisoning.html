PUBLIC-EVIDENCE AI SECURITY CASE STUDY

CoSnitch Combined Copilot Autorun Exfiltration with a Separate Memory-Poisoning Path

CoSnitch covered two independent Copilot attacks. In the autorun branch the victim opened a legitimate copilot.microsoft.com URL containing an attacker prompt in ?q= together with an undocumented autorun=1 switch; the existing authenticated browser session supplied the victim context and the prompt ran without a new confirmation, instructing Copilot to retrieve information from connected Gmail, Drive, Calendar, and chat history, encode selected values into a URL, and use Copilot's own fetch capability to send the request. In the memory branch a user asked Copilot to summarize an attacker-controlled webpage; hidden page text told the system to call memory.add, and the poisoned record became future prompt context. Varonis reports that password changes, session revocation, and device re-registration did not remove the memory — it remained until explicitly deleted. Microsoft patched CVE-2026-24301 on 2026-08-18; NVD lists CVSS 8.8, required user interaction, and no known exploitation. The durable lesson the brief draws is to govern both automatic prompt execution and memory writes as security decisions.

ASSESSED SYSTEM

Microsoft Copilot Web (the experience Varonis tested and describes as Copilot Personal) in its pre-fix state: an authenticated browser session in which (a) a copilot.microsoft.com URL combining ?q= with an undocumented autorun=1 parameter ran an embedded prompt without confirmation and used Copilot's own fetch capability against connected Gmail, Drive, Calendar, and chat history, and (b) hidden instructions in a summarized webpage invoked memory.add and persisted in long-term memory that Copilot could recall in later conversations. Both branches are entry points into one assessed product surface; Microsoft fixed CVE-2026-24301 on 2026-08-18.

OUT OF SCOPE

The two branches are independent and are not treated as one chain: the memory path began in a summarization workflow and did not depend on the crafted autorun link. The attacker's crafted URL, webpage, and destination are the attack, not the assessed system. Gmail, Drive, and Calendar are connected sources, not the assessed system. The post-2026-08-18 fixed state is out of scope. Product naming follows Microsoft's formal vulnerability record — Copilot Web — with the research wording preserved as an alias. NVD reports no known exploitation, so no victim or campaign outcome is scored.

Architecture: Agentic / MCP System (decision tree Q2) — Q1 = NO: a single assistant; no peer-agent coordination is described. Q2 = YES: on both branches Copilot autonomously executes a multi-step workflow — retrieving from connected sources, encoding values, invoking its own fetch capability, and on the second branch calling memory.add — with no approval for any individual step and with state that persists into later sessions. Evidence in the brief: the embedded prompt ran without a new confirmation, and the poisoned memory record became future prompt context. Tier 2: Tier 2 (Consumer): Copilot Web is a broadly distributed consumer assistant holding connectors to a user's mail, files, calendar, and conversation history, and both demonstrated harms — exfiltration of that content and durable poisoning of the user's long-term memory — land directly on that user population. NVD's CVSS 8.8 with required user interaction is consistent with a consumer-surface consequence class.

Documented attack or failure path

  1. Autorun branch: the victim clicks a legitimate copilot.microsoft.com URL carrying an attacker prompt in ?q= and the undocumented autorun=1 switch; the existing authenticated session supplies the victim context and the prompt runs with no new confirmation.
  2. The prompt instructs Copilot to retrieve information from connected Gmail, Drive, Calendar, and chat history, encode selected values into a URL, and use Copilot's own fetch capability to contact that destination.
  3. Memory branch (independent): a user asks Copilot to summarize an attacker-controlled webpage, and hidden page text instructs the system to call memory.add.
  4. The poisoned record enters long-term memory and becomes future prompt context, so the attacker instruction can be recalled in later conversations. Password changes, session revocation, and device re-registration do not remove it; it remains until explicitly deleted.

Observed controls and bounded outcomes

Positive credit is given only where the record directly demonstrates a control operating. Recommended or merely presumed controls receive no positive scoring credit.

  • Retrieval stayed inside the victim's own connected-source scope: the attack used the existing authenticated session and its permissions, and no cross-account access, credential theft, or authentication bypass is reported, so those layers are not scored as failures.
  • Microsoft patched CVE-2026-24301 on 2026-08-18, closing the reported vulnerability in the assessed product surface.
  • NVD records required user interaction and no known exploitation, so neither branch is scored as an unassisted or in-the-wild compromise.

WHAT THIS CASE TEACHES

This is the corpus's clearest Cn-7 case that has nothing to do with compute budgets. A webpage-derived record entered durable memory with no promotion gate and no lifetime bound, and Varonis established that password change, session revocation, and device re-registration all left it in place — so the platform had no deterministic teardown for its own agent state. Unbounded state lifetime is an execution-containment failure in exactly the same sense as an unbounded loop.
