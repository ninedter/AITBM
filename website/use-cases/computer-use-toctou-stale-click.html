PUBLIC-EVIDENCE AI SECURITY CASE STUDY

Computer-Use TOCTOU: The Agent Clicked a Screen It Had Not Rechecked

A computer-use agent selected a benign Continue button from a screenshot, paused to reason, and later clicked the same coordinates after the page had replaced that control with Outlook's Send button. The page first displayed the Continue button and embedded an indirect prompt asking the agent to calculate 1+1 through bash; that harmless calculation was a timing primitive, stretching the reasoning interval by about four to five seconds. During the gap the agent retained the coordinates selected from its earlier screenshot while the page opened a prefilled Outlook compose view and aligned the Send button with the former Continue button. The agent did not re-observe the target immediately before dispatching the click, so the stale coordinate sent an email whose body and destination the attacker had already chosen. Jun Kokatsu originally reported the browser computer-use race against OpenAI Operator; Rehberger reproduced the failure class with Claude Computer Use and credited that discovery. Rehberger reports that Anthropic's Cowork added a pre-action check requiring the relevant pixels to remain unchanged, and states this is evidence for the control pattern rather than proof that every implementation enforces it.

ASSESSED SYSTEM

A browser-driving computer-use agent as configured at reproduction time — Claude Computer Use in Rehberger's test — which selects an action target from a screenshot, reasons for an interval, and then dispatches a click at the coordinates chosen from that earlier observation without re-observing the target immediately before the click. Representative configuration: any computer-use agent whose action authority derives from a screenshot taken before the inference interval and that acts on raw coordinates rather than a revalidated element identity.

OUT OF SCOPE

The attacker's page, its embedded prompt, and its timing primitive are the attack, not the assessed system. Outlook is the target application, not the assessed system. Anthropic's Cowork surface is explicitly excluded: the brief reports that Cowork added a pre-action check requiring the relevant pixels to remain unchanged, and states that this is evidence for the control pattern rather than proof that any given computer-use implementation enforces it — crediting it here would score a different product. OpenAI Operator is out of scope as the original report surface; Jun Kokatsu's prior discovery is recorded as attribution, not as assessed evidence.

Architecture: Agentic / MCP System (decision tree Q2) — Q1 = NO: one agent, no peer coordination. Q2 = YES: the agent runs an unattended perceive-reason-act loop against a live browser, maintains task state across observations, and dispatches clicks and a bash task without per-action human approval. Evidence in the brief: the agent selected a target from a screenshot, paused to reason for four to five seconds, ran the page-requested bash calculation, and then dispatched the click on its own. Tier 2: Tier 2 (Consumer): a computer-use agent operates inside an individual user's authenticated session across their own applications and accounts, and the demonstrated harm — an email written by the attacker and sent from the user's account to a destination the attacker chose — lands on that user and their correspondents rather than on an internal service. The laboratory nature of the reproduction is carried by the ACI fidelity factor (0.70), not by lowering the tier.

Documented attack or failure path

  1. The page displays a safe-looking Continue button and embeds an indirect prompt asking the agent to calculate 1+1 through bash.
  2. The agent selects the Continue button's coordinates from a screenshot and runs the requested calculation, which stretches the reasoning interval by about four to five seconds.
  3. During that gap the page opens a prefilled Outlook compose view and aligns the Send button with the coordinates the Continue button formerly occupied; the email body and destination are already attacker-chosen.
  4. The agent dispatches the click at the retained coordinates without re-observing the target, and the email is sent — an action that no longer matches the screen the model reasoned about.

Observed controls and bounded outcomes

Positive credit is given only where the record directly demonstrates a control operating. Recommended or merely presumed controls receive no positive scoring credit.

  • No control inside the assessed configuration is evidenced as having interrupted the disclosed path. The pre-action pixel-stability check the brief describes was added to a different product surface (Cowork) and the brief states explicitly that it is evidence for the control pattern, not proof of enforcement in the assessed implementation.
  • The attack required no credential theft or session forgery: it used the user's own already-authenticated Outlook session, so the authentication and session layers are not scored as failures.
  • The brief records the class as originally reported by Jun Kokatsu against a different product, so the reproduction is scored as a class demonstration rather than as a defect unique to one vendor.

WHAT THIS CASE TEACHES

Computer-use agents introduce a physical gap between perception and action, and AITBM prices it as a Containment failure rather than a perception failure. The screenshot was accurate when taken and the model reasoned correctly about it; what was missing is any rule that an observation expires. Cn-6 is the sub-metric that would have caught it regardless of timing, because an email is a delegated-irreversible action and no observation, fresh or stale, authorises one.
