PUBLIC-EVIDENCE AI SECURITY CASE STUDY

DuneSlide: Two LLM-Controlled Paths Escaped Cursor's Terminal Sandbox

DuneSlide exposed two independent Cursor 2.x flaws that converge on one asset. An indirect prompt injection delivered through malicious MCP output or poisoned web-search content could make the agent authorize an out-of-project working directory: the model selected working_directory for run_terminal_cmd and Cursor added that directory to the sandbox write allowlist without proving it remained inside the project root (CVE-2026-50548). Separately, the Write tool tried to canonicalize a destination before enforcing project scope; for a write-only symbolic link whose target did not yet exist, canonicalization failed and Cursor continued instead of denying the write (CVE-2026-50549). Either route could overwrite Cursor's cursorsandbox helper inside the application bundle, after which a later command ran without the intended terminal sandbox. The brief keeps the two phases separate: each flaw supplied a route to corrupt the enforcement component, and execution occurred when a subsequent command used that component. Cursor 3.0, released 2026-04-02, contained both fixes before Cato published on 2026-07-01.

ASSESSED SYSTEM

Cursor 2.x in its pre-3.0 state, running an agent session that consumes MCP output and web-search content: run_terminal_cmd accepts a model-selected working_directory that Cursor adds to the sandbox write allowlist without proving it stays inside the project root (CVE-2026-50548), and the Write tool canonicalizes a destination before enforcing project scope, continuing instead of denying when canonicalization fails for a write-only symbolic link whose target does not yet exist (CVE-2026-50549). Both paths reach the same asset: Cursor's cursorsandbox helper inside the application bundle.

OUT OF SCOPE

The malicious MCP output and poisoned web-search content are the attack, not the assessed system. Cursor 3.0 and later is out of scope: it shipped on 2026-04-02 containing both fixes, three months before Cato published. The underlying model is not assessed — the finding is that an LLM-selected parameter was treated as a security decision, not that the model behaved defectively. No in-the-wild exploitation is reported, so no victim or campaign outcome is scored.

Architecture: Agentic / MCP System (decision tree Q2) — Q1 = NO: a single coding agent; the MCP server is a tool source, not a coordinating peer agent. Q2 = YES: the agent autonomously plans and executes multi-step file and terminal operations under a session goal, selecting tool parameters itself and invoking run_terminal_cmd and the Write tool without per-action approval. Evidence in the brief: the model selected working_directory for run_terminal_cmd, and a later prompt injection invoked the modified helper. Tier 3: Tier 3 (Internal): an AI coding IDE is developer tooling operating inside the organisational boundary, the same treatment given to the comparable AI coding-agent cases. The severity of unsandboxed host code execution is carried by Cascade Potential and the Containment scores, not by raising the tier.

Documented attack or failure path

  1. The attacker places instructions in content the agent will read — malicious MCP output or poisoned web-search results — without needing to type into the local session.
  2. Branch one (CVE-2026-50548): the model selects an out-of-project working_directory for run_terminal_cmd and Cursor adds it to the sandbox write allowlist without proving it remains inside the project root, turning an optional tool argument into a sandbox policy decision.
  3. Branch two (CVE-2026-50549): the Write tool canonicalizes a destination before enforcing project scope; for a write-only symbolic link whose target does not yet exist, canonicalization fails and Cursor continues instead of denying, so a failed path check becomes permission.
  4. Either branch overwrites /Applications/Cursor.app/.../cursorsandbox, Cursor's helper for launching sandboxed commands.
  5. A later prompt injection invokes the modified helper, and the command runs without the intended terminal sandbox — a separate phase from the write that corrupted the enforcement component.

Observed controls and bounded outcomes

Positive credit is given only where the record directly demonstrates a control operating. Recommended or merely presumed controls receive no positive scoring credit.

  • A sandbox and a project-scope enforcement layer both existed and are the components the attack had to defeat: run_terminal_cmd ran under a terminal sandbox and the Write tool did attempt project-scope enforcement. The brief characterises the defects as an unvalidated policy input and a fail-open check rather than as absent controls.
  • The two flaws are recorded as separate findings with separate CVEs and separate preconditions; neither is scored as requiring the other.
  • Cursor 3.0 shipped both fixes on 2026-04-02, three months before publication, so the disclosed paths were closed in the current release at the time of analysis.

WHAT THIS CASE TEACHES

Cn-6 scores 0.00 for a reason the per-action view would miss: the write that overwrote cursorsandbox and the command that later ran unsandboxed are different hops, and neither is individually catastrophic. The worst-case composition rule exists precisely for this shape — an irreversible step hiding inside a chain whose visible steps look ordinary — and nothing in the assessed configuration enforced it.
